# StockManager 第六阶段计划：主力行为统计追踪与高维研究系统

StockManager 是 A 股研究型筛选平台，禁止自动交易；本系统输出的是统计异常和潜在资金行为状态，不证明特定“主力”身份，所有结果仅供研究参考，不构成任何投资建议。

本阶段的架构与任务拆分代理为 Codex；实现、测试、调试与代码审查代理为 DeepSeek V4 Flash；Qwen3.8:27b 仅在实现验收后按完整任务包起草注释和技术文档。

## 1. 阶段定位

P6 是三个阶段中规模最大、研究不确定性最高的模块，因此排在 P4 并发数据读取、P5-A 回测和 P5-B CAPM 之后。

本阶段不把“主力到场”当作数据库中已知事实，而把它定义为一个待验证的潜在状态：价格、成交量、成交额、市场残差和时间结构出现联合异常后，模型输出异常分数、状态概率或变化点，再由 P5 的事件研究与样本外回测判断这些状态是否具有稳定解释力。

## 2. 可行性分级

### 2.1 当前数据可实现：日频代理追踪

现有 `DailyBar` 包含开、高、低、收、前收、成交量、成交额和交易状态。基于这些字段可以研究：

- 异常成交量与异常成交额。
- 价格区间、收盘位置、跳空和量价背离。
- 基于成交额的流动性冲击指标。
- 相对市场的 CAPM 残差异常。
- 波动率、相关结构和多变量变化点。
- 异常状态的持续、增强、衰减和退出。

这些只能称为“潜在资金行为”或“主力行为代理”，不能声称识别了真实机构身份或真实净流入。

### 2.2 需要扩展数据：增强日频追踪

若后续能够在 Baostock 当前数据源策略内取得并正规同步，可考虑增加：

- 换手率和流通股本。
- 行业、板块和市值，用于横截面中性化。
- 复权因子、公司行为和更完整的历史股票状态。

任何新增外部字段都必须通过 Provider 抽象和 `DataSyncService` 进入本地存储，不得由模型或规则自行联网。

### 2.3 当前范围不可宣称：真实资金流与账户级主力

仅用日线 OHLCV/amount 无法直接恢复委托方向、席位、账户或真实主动买卖净额。若研究目标升级到逐笔、Level-2、龙虎榜席位或真实资金流，需要单独的数据源与许可 ADR；在用户批准前不纳入 P6。

## 3. 阶段目标

1. 建立可复现、可版本化的日频特征管线。
2. 先实现透明的稳健统计基线，再评估高维模型。
3. 输出异常分数、状态和置信信息，不输出不可证实的“主力已进场”断言。
4. 使用 P5 的 CAPM 残差、事件研究和回测验证状态与未来结果的关系。
5. 严格分离特征生成、模型拟合、模型推断、验证和展示。
6. 所有筛选和推断只读取本地数据库，并通过 P4 读取端口访问。

## 4. 排除范围

- 不进行自动下单、持仓管理或实盘预警交易。
- 不从回测结果反向挑选最优阈值后宣称样本外有效。
- 不在 Rules 中训练模型、读数据库、读文件或访问网络。
- 不在第一版引入深度学习、GPU 或分布式训练。
- 不将缺失值自动填零，不把停牌日当作普通零成交日。
- 不在无标签条件下把异常分数伪装为校准后的真实概率。

## 6. 数据与特征契约

### 6.1 输入元数据

每次特征和模型运行必须包含：

- 数据集 ID、来源、生成/同步时间、复权方式。
- `Asia/Shanghai` 交易日范围和数据截止时点。
- 股票池及其历史时点语义。
- 特征版本、模型版本、训练窗口和推断窗口。
- P5 CAPM 基准与残差版本（若使用）。

### 6.2 第一批候选特征

最终公式和窗口在 P6-1 冻结，候选包括：

- 对数收益、隔夜跳空、日内实体和振幅。
- 收盘位置值；当 `high == low` 时必须有明确不可计算语义。
- 成交量与成交额的滚动中位数偏离、MAD 稳健 z-score。
- 量价相关、量价背离和成交额冲击。
- `abs(return) / amount` 类流动性代理；成交额为零时不可直接除法。
- CAPM 残差、残差波动和残差累计偏移。
- 市场横截面分位数与稳健标准化。
- 多窗口趋势、波动和异常持续性。

特征必须只使用推断时点及以前的数据。任何横截面标准化只能使用同一已完成交易日当时可见的股票集合。

## 7. 模型路线

### 7.1 Level 0：确定性规则基线

以少量透明条件组合形成基线异常分数，用于校验数据与解释链，不作为最终模型。示例维度为异常成交、正向残差、收盘位置和异常持续性；具体阈值不在计划阶段擅自决定。

### 7.2 Level 1：稳健单变量与多变量统计

- 滚动中位数/MAD。
- EWMA 或 CUSUM 变化检测。
- 稳健协方差或收缩协方差下的多变量距离。
- 控制特征尺度、共线性和小样本不稳定。

### 7.3 Level 2：高维降维与状态识别

- PCA 或等价降维提取共同异常因子。
- 变化点检测识别状态切换时间。
- 只有在有足够证据和稳定性后，才评估隐状态模型；模型状态必须通过可观测特征解释，禁止把任意状态编号直接命名为“主力”。

### 7.4 监督模型门禁

只有获得独立、时间点可用且许可明确的标签后，才允许训练监督分类或概率模型。没有标签时输出 `anomaly_score` 或 `state_score`，不输出伪校准 `probability`。

## 8. 输出契约

拟议 `PotentialCapitalPresenceSignal` 至少包含：

- 股票代码与检测交易日。
- `score`、分数范围和方向。
- `state`：如 baseline、emerging、persistent、cooling；名称在 P6-0 冻结。
- 变化点或状态起始交易日。
- 使用的特征及其贡献摘要。
- 数据、特征和模型版本。
- 置信或稳定性指标；无校准证据时不得称为概率。
- 缺失数据、停牌、窗口不足或模型不可用的明确原因。
- 研究用途免责声明。

## 9. 验证框架

### 9.1 事件研究

对信号发生后的固定交易时段计算：

- 原始收益与基准超额收益。
- CAPM 残差累计值。
- 最大有利/不利变动。
- 信号持续时间和衰减。

窗口必须按交易时段计算，并严格位于信号之后。

### 9.2 样本外验证

- 使用滚动或扩展窗口训练，下一时间段推断。
- 参数、标准化统计量和 PCA 载荷只能由过去数据估计。
- 阈值选择与最终评估必须分离。
- 多股票、多特征和多窗口试验需要记录多重检验风险。

### 9.3 P5 回测复用

P6 不再建设第二套回测引擎。信号通过 P5 `BacktestEnginePort` 转换为目标权重并进行研究验证，使用相同成本、不可交易和反前视规则。

## 10. 任务分解

### P6-0：研究问题与可观测定义冻结

- 明确“到场时间”是首次变化点、状态进入时间还是连续满足条件的首日。
- 明确输出是异常分数、状态还是经校准概率。
- 固定当前日频代理范围和禁止表述。
- 形成模型卡与数据缺口清单。

验收：每个业务词都有可计算定义；未知标签和不可观察变量被明确标出。

### P6-1：特征目录与纯特征管线

- 为每个特征定义公式、单位、窗口、端点、缺失值和零分母行为。
- 实现排序、去重、停牌和复权一致性校验。
- 特征输出版本化并可追溯原始数据快照。

验收：人工 fixture 可逐项计算；无未来数据泄漏；无网络和数据库副作用。

### P6-2：稳健统计基线

- 实现滚动稳健标准化、EWMA/CUSUM 和透明组合分数。
- 输出贡献解释和不可计算原因。

验收：异常注入 fixture 能在预期日期触发；常态、零成交、停牌、缺失和极端值不产生虚假稳定信号。

### P6-3：高维模型研究原型

- 评估 PCA、协方差收缩、多变量距离和变化点方法。
- 记录每个模型的依赖、样本要求、复杂度和稳定性。
- 只允许一个通过离线验证的模型进入正式推断路径。

验收：与 Level 1 基线对比；模型重跑确定；输入列顺序改变不应改变语义；特征共线和样本不足显式处理。

### P6-4：walk-forward 拟合与模型注册

- 分离拟合期、校准期和验证期。
- 保存模型版本、训练范围、参数、特征版本和随机种子。
- 禁止运行时临时用未来全样本重训。

验收：同一模型版本和输入快照可复现；模型缺失或版本不兼容时明确失败。

### P6-5：信号服务与本地存储

- 服务层通过 P4 读取特征窗口并编排已注册模型。
- 保存信号、状态变化和解释摘要。
- Rules 若消费 P6 结果，只接收结构化上下文，不自行查数据库。

验收：服务断网运行；Provider 不可达不影响已同步数据推断；读写边界符合现有分层。

### P6-6：事件研究与 P5 回测集成

- 生成事件队列、前向窗口和对照组。
- 通过 P5 回测端口验证信号组合。
- 输出含成本和偏差说明的研究报告。

验收：信号日与收益窗口严格错开；同一数据集结果确定；禁止把样本内结果写成已验证事实。

### P6-7：解释界面与研究工作流

- 展示状态时间线、特征贡献、数据版本、模型版本和警告。
- 用户可查看为什么产生或没有产生信号。
- 界面不得显示无依据的“主力已进场”确定性文案。

验收：空数据、窗口不足、模型不可用和异常状态均有清晰展示；API 不包含模型训练逻辑。

### P6-8：压力测试、审查与文档同步

- 使用 P4 并发读取全市场特征窗口并记录性能、内存和失败恢复。
- 完成数据泄漏、数值稳定、并发一致性和偏差审查。
- 验收后更新模型卡、接口、使用限制和开发记录并同步 `project_doc`。

验收：DeepSeek V4 Flash 完成实现、测试、调试和代码审查；Qwen 文稿经代码事实核对后才可同步。

## 11. 关键决策门禁

1. “主力到场时间”的精确定义。
2. 是否接受“潜在资金行为状态”这一非身份识别表述。
3. 第一版仅使用现有日线字段，还是等待换手率/流通股本等增强数据。
4. 横截面是否需要行业、市值中性化；缺少数据时如何降级。
5. 模型输出是排序分数、离散状态还是概率。
6. 训练、校准和验证的时间区间。
7. P5 回测中的持有期、再平衡和组合构建方式。

## 12. 测试矩阵

- 空数据、单行、窗口不足、无序和重复日期。
- `None`、`NaN`、无限值、零成交量、零成交额和 `high == low`。
- 连续停牌、复牌、ST、涨停、跌停和退市边界。
- 复权元数据不一致。
- 正常状态、单日尖峰、渐进累积、结构突变、异常衰减。
- 高共线特征、常数列、维度高于样本数。
- 训练/验证边界和未来数据泄漏检测。
- 串行与 P4 并发读取结果一致。
- 固定随机种子下模型和信号确定性。
- 断网推断与 Provider 不可达断言。

## 13. 完成定义

1. P6 输出被准确表述为统计代理，不冒充真实账户或资金流事实。
2. 特征、模型、数据和验证版本全部可追溯。
3. 所有拟合只使用推断时点之前的数据。
4. P6 复用 P4 读取、P5-A 回测与 P5-B CAPM，不建设重复基础设施。
5. 关键边界、数值稳定和数据泄漏测试离线通过。
6. 不新增自动交易、实盘连接或 Provider 反向依赖。
7. DeepSeek V4 Flash 完成实现与最终技术验收。
8. 验收后的技术文档包含规定 frontmatter，并同步到 `/Users/douzihao/StockManager/project_doc`。
