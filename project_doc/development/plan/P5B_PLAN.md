本文明确区分用户已确认、Agent 建议、历史核验事实与待决项。旧 P5 计划的 CAPM 设想仅作为下文第 9～10 节的规划输入；尚未确认的接口、参数、任务粒度和验收口径不得视为已冻结。当前不绑定模型职责，也未发生独立代理审查。

用户要求实施时另行维护 [CAPM数据处理](../implementation/CAPM数据处理.md)，统一记录指数与数据来源、计算公式、参数、缺失处理、实际实现和验证证据。本计划保留范围、决策与待决项；处理手册随实现同步更新，不以新增文档代表服务已实现。

## 2. 当前事实与旧计划差异

### 2026-09-03 同步同等级补充（当前用户确认，覆盖下文早期同步方案）

用户要求 CAPM 输入与股票筛选池输入独立，但复用股票池完整同步设施。实现目标与验收如下：

- 数据集：股票仍为 `market/qfq`；参考数据为 `capm/unadjusted`，其中 `unadjusted` 仅表示指数原始点位；利率复权不适用，收益版本另存，不能伪造为股票 qfq。
- 同步路径：两者共用 `SyncPipeline`、`SerialFetchWorker`、`StagingWriter`、`GenerationCommitter` 和 `ReadinessGate`。CAPM 专用 Planner/Verifier 负责目录依赖展开、逐指数缺口与利率覆盖，不套用股票池 95% 门槛。
- 目录任务成功后，在事务中展开逐指数区间任务；任务数、抓取错误、批次来源/时间/摘要、校验明细持久化。各自拥有计划、candidate、active generation、后台 runner 锁、进度与日志，共用 Provider 的进程锁、文件锁、串行限速和 socket 超时。
- 成功任务不重拉；中断可续传；失败不发布且必须显式点击重试并遵守冷却。每次以本地真实数据检查尾部及内部缺口，只为缺口发请求。目录和利率端点没有逐日查询粒度，新目标日刷新快照；同目标日修复复用已成功的本地快照。
- 仅 Baostock：目录先过滤证券代码类型与宽基/行业范围，ETF、基金、债券、明确风格/主题不混入。`(收益)`、`全收益`、`净收益` 分别保留来源收益版本。历史缺日的发布验收按下方「来源可用数据验收」执行；成功响应的来源缺口留存证据，不制造价格、不将这些日期用于 CAPM。真实抓取失败、非法数据及默认基准在整个目标范围完全无价格仍阻止发布。
- UI：数据页集中两个入口「股票筛选池回补和同步」「CAPM 回补和同步」，后者使用同一后台脚本的 `--dataset capm`，无需等待长 HTTP 请求。独立展示进度、错误、已发布计数、来源代码到内部指数 ID 的映射、真实覆盖和来源受限区间；进程管理按两种任务分别显示停止入口。
- 读取：CAPM 仅读取已发布 generation，并在一次 SQLite 只读事务中取得股票 qfq、指定指数和利率。缺少参考版本、指定指数日期缺失或版本在门禁和读取之间变化，明确拒绝，不联网、不换基准。
- 接口：`POST /api/sync/capm-reference` 接受可选 `start/end`，缺省采用后端配置历史范围和最新已完成交易日；`GET /api/sync/pipeline/progress?dataset_id=capm` 返回独立计划/后台任务状态及错误；`GET /api/sync/capm/status` 返回已发布的目录映射与覆盖。原股票端点保持兼容。
- 存储：schema 4→5 事务迁移，为三类参考表增加 batch 绑定与 staging，同时增加 `sync_runners`。不搬迁数据库、不删除现有股票行情。版本提升至 1.15.0。
- 验收：离线覆盖独立发布、成功跳过、内部缺口、次日增量、失败/冷却/断点、来源无数据、共享锁、API 路由隔离、重复点击、唯一 DOM ID 和发布后 CAPM 计算。真实网络验收只使用隔离库，不把小范围通过描述为全量八年数据完成；最终证据见《CAPM数据处理》9.5。

## 3. 建议的架构边界

建议把 P5-B0 的数据工作拆为指数目录与可用性核验、指数行情入库、历史成分及权重入库、利率契约、收益输入契约五项；在已确认范围内细化设计，未决口径确认后再冻结公开接口和 migration。

1. **指数目录与行情独立建模**：建议新增独立的指数目录和指数日线存储，名称暂拟 `index_catalog` / `index_daily_bars`。目录覆盖已确认的宽基、行业、风格类别；建议记录编制机构、分类体系、内部稳定身份、Provider 代码映射、收益版本、来源可用性与本地覆盖状态，不把固定的几个指数代码写进 CAPM。继续使用本地 SQLite；指数不进入股票筛选池，也不被要求提供股票 ST、PE 或交易执行字段。
2. **同一同步入口与增量补齐**：用户已确认按增量补数据；指数经 `DataSyncService` 编排现有 Provider，沿 Planner → 串行 Worker → Staging → Verifier → Committer 发布。按已有覆盖补尾部、内部缺口和新增范围；保持锁、超时、限速、失败状态与成功数据防重复拉取，见第 14 节。
3. **独立数据集身份**：指数数据集与 `market/qfq` 区分；同步幂等身份须涵盖指数集合及目录修订、来源、收益版本、日期范围等。增加一种指数不能被旧“当日已成功”误判为已有，也不能因此重新抓取其他成功指数。具体主键与兼容迁移待设计。
4. **通过 P4 只读端口访问**：建议为指数与利率提供明确读取契约；CAPM 服务不持有 Provider，不访问网络。分析输入固定资产、指数、利率各自的数据版本与内容摘要。
5. **收益构造与数学分离**：首期个股收益从本地行情构造，明确前置收盘观察和收益定义，再按同一交易区间对齐。CAPM 核心只消费结构化超额收益。组合净值、费用/现金流与首日基准净值的接入契约属于维护期扩展。
6. **可复现性不作过度承诺**：[DataSync 数据库 ADR](../architecture/ADR_P5_DATASYNC_DATABASE.md) 明确当前仅支持 active generation，旧 manifest 不保证旧行情行可重放。历史查询已移出首期；建议完整输入快照和旧版本精确重跑也留待维护期专门讨论，首期只承诺结果与必要元数据持久保存，不声称已批准输入快照或精确重跑功能。分析读取一致性和错误缓存防护仍须具备。
7. **目录、行情与成分关系分开**：目录回答“有哪些指数”，行情回答“指数如何变化”，历史成分及权重回答“某时点由哪些股票构成”。历史成分及权重已确认纳入首期；建议分别表达来源能力和同步状态，有指数行情不代表有历史成分/权重。须表达生效时间、观察/可用时间与来源，不得用当前成分回填过去。时点存储建议见第 7 节。

建议冻结的时点与缺失行为：

1. 分别保存“数据对哪个时点成立”“当时何时可知”“系统何时获取”。抓取时间不能冒充历史公告时间；未知生效/发布时间保留未知，不能强行推断。只能证明观察日名单时，不承诺覆盖两个观察日之间的每一天。
2. 同一来源修订后的快照另存修订与来源证据，不能覆盖旧快照。成分退出通过完整名单差异或正式变更记录表达，部分响应不能被解释为其他股票已调出。
3. 权重缺失不等于 0；没有权重的成分仍可保留为成员，权重可用性单独报告。不自动等权、不将残缺权重重新归一化冒充完整权重，不把定期快照扩展为每日官方权重。是否提供派生估计属于另一个待授权功能。
4. 历史关系查询与“当时已知信息”的研究查询须区分。用于形成历史筛选信号时，必须满足已确认的可用时间规则；仅有事后历史快照时应报告 PIT 证据不足。
5. 成分证券身份不能依赖当前活跃股票池中的存在性。保存历史调出/退市成员不自动授权扩大股票行情抓取或修改既有筛选池。
6. 成分与权重各自纳入计划身份、staging、逐快照验证、发布和 P4 本地读取；遵循成功防重复、显式缺口与失败记录。旧快照的实际明细须保留，不能仅依赖当前 generation manifest 宣称历史可重放；具体行版本与 migration 方案需补充数据库 ADR 后实施。

建议离线验收场景（尚未执行）：

- 固定 fixture 包含两次成分调整，可正确查询调整前后名单，且当前名单不会回填历史。
- 同一成员在两个权重时点保留不同数值；重复导入保持幂等，来源修订可追溯且旧值不被覆盖。
- 成分完整而权重缺失、仅返回局部名单、重复成员、非法权重、缺少发布时间分别产生可辨识状态；权重和的容差由来源精度与口径确认，不自行取固定值。
- 再现“公告已发布但尚未生效”和“历史记录后来修订”两种情况，证明不会把未来生效或未来修订信息混入当时信号。
- 含已退市成员的历史快照能读取；断网时目录、行情、成分和权重查询均只依赖本地已发布数据。

历史目标跨度与权重快照频率已确认（B-I4/B-I8）；具体来源覆盖不足时列出缺失指数、日期、数据类型与原因，再决定后续范围，不擅自切换来源。

### Baostock 存款利率接口详查

- **用途与参数**：查询存款利率记录；`start_date`、`end_date` 为可空的 `YYYY-MM-DD`，官方定义按**发布日期**筛选，本地 SDK 注释说明包含端点。没有银行、币种或期限选择参数；期限作为不同列返回。
- **字段**：`pubDate`；活期 `demandDepositRate`；整存整取 `fixedDepositRate3Month/6Month/1Year/2Year/3Year/5Year`；零存整取、整存零取、存本取息 `installmentFixedDepositRate1Year/3Year/5Year`。这里的斜杠表示同一前缀的多个完整字段名。
- **口径证据**：2015-03-01 样例的活期、三个月、半年、一年、二年、三年分别为 0.35、2.10、2.30、2.50、3.10、3.75，与中国人民银行同日基准表逐项一致；中国银行同日一年期为 2.75。由此推断样例为央行基准口径，不能把“中国人民银行”和“中国银行”混为同一机构。按对应央行表单位，样例 2.500000 表示年利率 2.50%，归一化为 0.025；正式适配仍须校验实际响应单位。
- **返回类型**：官方文字称 DataFrame，但其示例与本地 0.9.3 源码实际先返回 `ResultData`，需检查 `error_code/error_msg`，通过 `fields`、`next()`、`get_row_data()` 等读取，再转换表格。官方第二张样例表存在列对齐/空项问题，不据此猜测五年期或分期存款值。
- **时间与缺失限制**：它是按发布日期查询的记录，不能假定每日一条。某个历史窗口内没有新记录，不代表该期间利率为零；构造适用序列还需起点之前的有效记录。央行官方说明自 2014-11-22 起不再公布五年期定期存款基准利率，字段存在不保证始终有值，不能用 BOC 五年期挂牌数值补齐央行序列。
- **验证边界**：2026-09-03 已读取 Baostock 新版官网的公开文档及本地 SDK；未调用远端利率数据接口。2015 年只是文档示例，不能据此声称实际数据仅到 2015 年，也不能声称目前仍持续更新。最早/最新记录、空值、服务可用性须在已授权的同步边界内另行验收。

### Agent 建议的实现边界（未实施）

1. 为央行存款基准利率定义可替换的专用读取/获取契约，优先在 Baostock 适配层封装 `query_deposit_rate_data()`，仅经 `DataSyncService` 编排访问。获取渠道记录为 Baostock，原始发布机构记录为经证据核实的中国人民银行，两者分别表达；CAPM 不持有 Provider，不硬编码 SDK。实际来源口径或覆盖不符时报告缺口，不静默换回 BOC，也不激活通用 Provider Registry 扩展计划。

3. 历史分析建议按每个区间起点当时有效、可用的央行存款基准利率构造同一期限代理序列；采用最新已生效记录属于明确的调息事件有效期映射，与填补未知指数行情不同。区间跨调息日的切分、端点归属和公告时点不明的处理须另行冻结；利率不变区间按实际自然日、固定 365 分母、单利转换已确认。今天的基准利率若应用于整段历史，应单独标记为当前利率情景，不能声称当时可得。
4. 央行存款基准年利率作为本项目已选的无风险利率研究代理，不等同于银行实际可成交报价或可每日退出的资产收益。建议标记 `rate_proxy_kind=central_bank_deposit_benchmark`，展示发布机构、品种、期限和时点；用户已确认区间计息按自然日、固定 365 分母和单利，不除以交易日数量，也不自动视为真实定存合同收益。
5. 初次入库包括研究起点之前最近一条有效利率版本及窗口内调息记录；CAPM 通过 P4 读取本地已发布利率。新增调息记录与成功历史记录分开管理，联网仍只发生于同步阶段，失败不得回退零利率、BOC 挂牌利率或其他未经确认的利率品种。
6. 建议离线验收覆盖：生效前后取值、未来公告排除、周末跨期、利率调整跨期、百分数转换（2.50% 对应 0.025）、同产品不同期限隔离、缺少起点有效记录、接口字段变化与缺失期限、来源修订、重复同步及断网分析。测试尚未执行。

## 9. CAPM 计算与结果契约草案

以下保留旧 P5 的研究方向，按本轮数据事实修订为建议；具体接口与参数在第 5 节待决项确认后冻结。

```text
R_asset,t - R_f,t = alpha + beta * (R_market,t - R_f,t) + epsilon_t
```

- 首期为个股超额收益回归；市场默认沪深300，`R_f,t` 由已选期限的央行存款基准年利率按待确认约定转换。P5A 组合接入留作维护期扩展。
- 首期在筛选截至日进行多窗口估计；自然日窗口、简单日收益、alpha 线性年化和252可调整默认已确认。股票至少半年有效历史属于准入门槛，达标后可计算最近 30 个自然日的窗口。半年有效性的精确定义、其他窗口集合与每窗口最少有效观察数仍待决定。逐日滚动曲线与残差波动扩展不纳入首期。
- alpha 原始值和年化值都展示、允许指标排序已确认；beta 无量纲，不另外生成“年化 beta”。建议结果包含 `alpha`、年化 alpha 及换算元数据、`beta`、`r_squared`、`observation_count`、实际窗口与结构化不可估计原因，同时保存配置、模型版本、基准身份、收益口径、利率发布机构/渠道/品种/期限、时点语义、单位、换算约定和输入版本/摘要。接口字段名为草案；残差序列与 P6 消费接口留待维护期。
- 按相同交易区间与 `Asia/Shanghai` 日历对齐，禁止按行位置拼接；是否允许删除缺失区间或缩短窗口须确认。重复日期、无序输入、非有限值、零市场超额收益方差、样本不足及口径不兼容必须有明确状态。排序标准化或拒绝无序输入的策略须统一，不能留下相互矛盾的契约。
- 股票价格输入明确使用 `qfq`，所有窗口保持一致；个股与指数均用简单收益率公式。指数价格/全收益版本及现金分红兼容性仍需审定，不能要求指数伪造 qfq 标签或擅自再次加入已计入的分红。前复权缺失或标签不符时明确报告，不能改用后复权或不复权继续计算；不默认用零利率、固定当前利率或手工曲线替代缺失数据。
- P6 残差消费保留版本化输出的想法，已确认不纳入首期；首期 API/UI 只调用本地研究服务，不包含回归算法或隐式联网。CLI 留待维护期。

### 12.2 流程与项目设置

1. 用户运行模板，先显示通过名单；固定筛选日期和实际模板内容。未点击股票显示“未请求分析”，不自动计算，不产生虚假结果；零通过不启动分析。
2. 用户点击某只通过股票，后端校验该股属于该次筛选运行，读取并冻结项目 CAPM 设置快照，自动启动其多窗口分析。具体点击布局与现有 K 线详情如何组合属于后续 UI 设计。
3. 只读取目标股票、项目基准及央行利率的本地数据。建议一次准备最大窗口和前置观察，再分别构造各窗口收益、校验样本并计算；界面显示“计算中”，随后补齐多组指标。
4. 展示各窗口日频原始 alpha、线性年化 alpha、beta 和状态；详情建议包含截至日、实际窗口、观察数、R²、利率品种/期限及无法估计原因。原始 alpha 与年化 alpha 分别标单位，年化因子默认252且可调整；beta 无量纲，R²不冒充显著性检验。
5. 结果经 Storage 保存 SQLite；事务提交成功后才能显示“已保存”，保存失败单独提示。结果补充不改写原筛选 `passed` 和规则理由。用户已允许按指标排序；建议显式选择窗口、指标及方向，只对已有有效结果排序，未计算/不可估计单独置后，不为排序自动计算未点击股票。具体排序交互待确认；二次筛选未授权，历史查询/导出不属于首期。
6. 切换股票、重新筛选或修改设置时，迟到响应只能更新所属分析与股票，不覆盖新视图。继续后台任务、取消和重启任务恢复策略另定。

项目设置归属已确认，默认沪深300、自然日窗口、简单日收益、alpha 原始及线性年化同时展示，年化因子默认252且可调整；利率默认央行人民币整存整取一年期且可调整、各窗口统一，并按实际自然日、固定365分母、单利换算。其他窗口集合、利率历史时间映射及区间端点/跨调息规则、半年有效数据及各窗口样本门槛尚未确认，不自行填写数值。设置变更影响新分析，旧记录保留当时配置快照；年化因子和利率365分母分开配置，具体设置契约见第 16.5～16.6 节。

股票复权在本期项目配置中固定为 `qfq` 并显式传递，不作为各模板或各窗口可独立覆盖的选项。读取端核对真实元数据，不通过修改标签把其他复权数据冒充前复权；不符合口径时返回明确错误。具体配置字段和 API 仍待实现契约冻结。

### 12.3 30 天估计窗口与央行利率期限

用户已确认多窗口展示、自然日窗口和日收益；股票须具备至少半年有效历史才能纳入 CAPM，准入后仍可计算最近 30 个自然日的指标。因此保留 30 天窗口，不把半年设为每次回归的最短窗口。拟议 **30/120/250/500** 中其他窗口及最终集合仍未冻结；半年有效性的精确定义不能自行写成 180 个交易日或 126 条观察。

- **估计窗口**决定使用多少历史；**利率期限**决定选择哪档存款基准年利率作为代理；**收益频率**决定每条回归观察跨多长时间。三者分别配置，不能机械一一对应。
- **窗口与利率计息分别确认按自然日**：对两个收益观察端点之间的无风险代理，使用实际日历跨度，计入周末和节假日。例如周五收盘至下周一收盘的区间跨 3 个自然日；CAPM 仍只增加对应的一条交易区间收益观察，不为周六、周日补造股票收益。窗口长度、日收益观察数量、利率计息天数分别记录。
- “实际自然日数”与“年分母”分开保存；用户已明确选定固定 365 分母与单利。利率不变时使用 `r_f = annual_rate_decimal × calendar_days / 365`，闰年分母仍为 365、闰日计入分子；跨年本身不改变分母。端点归属与跨调息切分仍待冻结，不能因为单利已确认就默认某种历史利率映射。
- 30 天窗口只取其自然日区间内真实交易日的日收益并获取所需前置价格，不把 30 个价格当成 30 个收益，也不把区间固定成 30 个交易日。共同有效观察数、区间端点和不足样本行为仍须冻结。
- 股票半年有效历史资格与具体窗口的有效样本数分别校验；有半年历史不代表最近 30 天没有停牌或缺口，也不代表能估计 500 天窗口。半年按六个日历月、固定天数还是有效观察数门槛，以及完整性要求，均待用户确认；八年数据保存目标不等于每次估计用八年。
- 本轮核对的央行人民币存款基准表列有活期，以及整存整取三个月、半年、一年、二年、三年；五年档有历史记录，但央行说明自 2014-11-22 起停止公布。该表没有一个月/30 天整存整取基准档，不能插值成伪造的官方期限。
- Baostock 文档另列零存整取、整存零取、存本取息的一/三/五年字段；它们是不同产品，字段存在不保证实际覆盖，不自动混入整存整取代理。本轮未调用远端利率接口。
- **各估计窗口共用同一利率期限已确认，当前默认央行人民币整存整取一年期、可由项目设置调整**；不因估计窗口是 30 天就寻找或切换到“30 天存款利率”。各窗口按实际自然日、365 固定分母、单利换算已确认；历史上匹配当时适用版本仍为建议，历史映射、区间端点和跨调息切分仍属 B-R2～B-R3，不默认除以 252。
- **截至日已确认固定为筛选日期**，另存实际计算时间；不得随点击时间自动改为今天。回归使用窗口内按约定有效的全部收益，不仅取历史上满足模板的日期，不用横截面股票代替时间序列。历史结果查询入口已移出首期。

来源：[央行存款基准表及五年档说明](https://www.pbc.gov.cn/zhengcehuobisi/125207/125213/125440/125838/125888/2887261/index.html)、[Baostock 官方字段](https://www.baostock.com/mainContent?file=depositRate.md)、[NYU 回归与窗口选择](https://pages.stern.nyu.edu/~adamodar/pdfiles/acf3E/book/ch4.pdf)。此处核对期限分类，不把旧表数值称为当前利率。

### 12.4 服务职责、一致性与错误

- 拟议编排服务关联筛选运行和点击请求，校验目标股、冻结项目配置，再调用 `CapmAnalysisService`。CAPM 服务经 P4 获取本地输入，构造收益并调用纯函数；写入走 Storage。名称与 API 路径尚未冻结，回归不放入 Web 控制器、模板或筛选规则。
- 新增筛选运行和分析标识；校验资产、指数和利率版本，防止同步发布导致跨阶段混用。现有 active generation 限制仍需专门设计，不能只增加版本字段便声称快照问题已解决。
- 前复权更新后，同一日期历史价格可能属于新的修订版本；全部窗口必须使用同一版 qfq。缓存身份包含复权方式及实际输入版本/摘要，新版数据产生新分析身份，保留旧结果和证据，不把旧缓存视为已基于新数据计算。
- 多窗口可共用一次一致的读取结果，不在筛选 worker 内嵌套读取/计算并发池，不为此引入微服务或消息中间件。
- 区分未请求、排队、计算中、可估计、不可估计、失败与取消。建议完整读取后按窗口报告样本不足或零方差，保留其他有效窗口；底层读取异常、快照变化、共享基准/利率缺失则明确失败，不发布混合输入的正常结果。
- 缺失值不填 0，不隐式缩短窗口或替换基准。用户已要求新股不纳入 CAPM、股票至少半年有效数据；资格判定在筛选截至日执行，不能用今天已满半年替代历史日期的资格。半年有效数据的精确定义、停牌/缺口删样本及各窗口最低观察数仍须确认；建议资格不足仅禁止 CAPM 计算，不改变原模板筛选名单。点击不触发 Provider、网络补数或无限重试。
- 相同股票、截至日、配置和输入版本可复用计算；缓存键不能只含股票或日期。不同模板仍须保留各自筛选来源。结果持久保存、计算缓存与完整输入快照是不同范围。

### 12.6 验收场景草案（未执行）

2. 不同模板读取相同项目设置，计算输入相同时指标一致；持久记录保留各自来源，未保存模板编辑可追溯。
3. 自然日窗口采用真实日收益，覆盖周末和长假；不把窗口天数当成有效观察数。半年资格按冻结后的定义覆盖不足、刚达标、停牌/缺口及筛选截至日边界；已具备半年有效历史的股票通过准入后，30 天计算仅取最近 30 个自然日的收益，不暗中扩为半年回归；资格不足的股票即使有 30 天数据也不计算。长窗口不足不冒充完整。
4. 连点、换股、重筛、改设置和数据更新后，分析身份正确，旧响应不覆盖新视图，重复请求不制造统计重复行。
5. 事务提交后通过 Storage 验证结果确已持久保存，包含日频 alpha、年化展示所需数值/换算信息及筛选截至日；保存失败不显示已保存，模板改名不改写历史名称。不要求首期历史查询界面，进行中任务取消/恢复按后续确认验收。
6. 断网可计算且不触发 Provider；读取失败和不可估计不以 0 或旧值冒充新指标。
7. 无风险代理按实际自然日、固定 365 分母、单利处理普通相邻交易日、周五至周一、长假、跨年和闰日；闰年分母不变，周末不添加股票观察。固定年利率 0.015 的三自然日区间结果应为 `0.015 × 3 / 365`，不加复利项；其他数值容差随计算契约冻结。利率在区间内变化时按最终确认的切分规则校验，结果记录天数、`ACT/365F` 与 `simple`。
8. 所有模板与窗口读取 qfq；传入或读到 hfq/unadjusted 时明确拒绝，不仅改标签。固定转增 fixture 验证收益不会把机械除权误算为亏损，现金分红场景按最终收益契约核验；旧/新 qfq 不得拼接，修订后旧缓存不命中且原结果保留。
9. 简单收益率与线性年化公式正确；默认因子252，日频alpha为0.0002时年化值为0.0504。调整因子后新分析采用新配置、旧结果保留原因子，利率365分母不联动变化；原始/年化同时显示、单位明确，beta不年化。选择窗口与指标后排序正确，同分与NULL按冻结规则处理；未点击股票不因排序触发计算或成为零值样本。

## 13. CAPM 结果规范化存储草案（保存目标已确认，schema 未冻结）

### 13.1 记录粒度与字段

用户要求按模板名、日期、alpha、beta 规范保存。逐股且多窗口时，**一条统计明细对应一个筛选来源下的一只股票、一个截至日、一个窗口及一版分析配置/输入**。四个字段全部保留，但必须补充股票和窗口等身份，才能区分同模板同日的多组结果。

建议统一表结构，不按模板名或日期创建动态表，保留未来扁平统计查询所需字段。历史查询/导出界面及专门查询模块已确认延期，不作为首期验收要求。

| 字段组 | 拟议字段及类型 | 约定 |
|---|---|---|
| 身份 | `analysis_id`、`screening_run_id`、`request_key`：TEXT | 关联筛选来源并去重，不用模板名当稳定主键 |
| 模板 | `template_id`：TEXT，`template_revision`：INTEGER，`template_name_snapshot`、`template_content_hash`：TEXT | 保留运行时名称和实际内容摘要；建议保存实际模板内容，改名不覆盖历史 |
| 股票/时间 | `code`：TEXT，`as_of_date`：日期语义，`calculated_at`：带时区时间戳 | 代码含市场；截至日固定为筛选日期，计算时刻另存；展示时区 Asia/Shanghai |
| 窗口 | `window_size`：INTEGER，`window_unit`、`return_frequency`：TEXT，实际起止日期，`observation_count`：INTEGER | `window_unit=calendar_day`、`return_frequency=daily` 已确认；半年资格的定义/判定证据另记，目标窗口与有效样本不混淆 |
| 结果 | `alpha`、`alpha_annualized`、`beta`、`r_squared`：可空 REAL，`alpha_period`、`status`、`reason_code`：TEXT | alpha 存原始日频回归截距的小数收益率，建议同时存展示用年化值及方法；beta 无量纲；不可估计存 NULL 和原因而非 0 |
| 配置/证据 | 基准 ID、项目设置版本/快照、收益口径、利率品种/期限/转换约定、输入版本/摘要、模型版本、alpha 年化方法及因子 | 默认沪深300，冻结精确收益版本；可按相同口径做统计，不能仅按当前设置反推历史年化值 |

股票分析记录显式保存 `adjustment=qfq` 及所用输入版本/内容摘要，供后续查询/统计使用，不能只从项目当前默认值反推历史记录。指数收益版本另存，利率不标为 qfq。

利率转换配置显式保存 `rf_accrual_day_unit=calendar_day`、`rf_day_count_convention=ACT/365F` 与 `rf_compounding=simple`，对应的业务值均已确认，字段名仍为 schema 草案；回归的 `window_unit` 和 alpha 年化配置独立保存。构造后的收益输入应能追溯每个区间端点与实际计息日数；这不扩展为已确认永久保存全部原始输入。

SQLite 日期/时间建议存校验后的 ISO 文本；“日期语义”不宣称 SQLite 存在独立日期存储类型。alpha/beta 不存带百分号字符串，不按 UI 精度截断；精度容差及非有限值校验随计算契约冻结。

### 13.2 表结构、版本与去重建议

- 暂拟 `capm_analysis_runs` 保存一次点击分析的模板来源、股票、截至日、配置和输入/模型版本；`capm_window_results` 保存其各窗口数值、观察数与状态。名称为草案，生产库尚未建表。
- 明细建议以 `(analysis_id, window_size, window_unit, return_frequency)` 唯一；一个分析身份下配置冻结，不混用不同基准或利率方法。
- 建议相同筛选运行、股票、完整设置与输入版本的重复点击复用同一分析身份；设置或数据变化创建新版本，保留旧结果，不能仅按模板名和日期覆盖。
- 关联、结果与状态按事务提交，数据库约束防并发重复；写入经过 Storage，P4 只读连接不写结果。请求去重键、失败重试留痕和“当前版本”的选择规则须在实现前冻结。
- 维护期统计视图可提供模板名、稳定 ID/revision、股票、截至日期、窗口、原始/年化 alpha、beta、基准、状态和分析版本。首期设计必要的写入/去重索引与结构化字段；不提前实现延期的历史检索、统计视图和导出模块。

### 13.3 后续统计边界

- **只有被点击股票有分析记录**。未点击不等于失败或 alpha/beta 为零；保存子集不能冒称模板全部通过股票的统计样本。
- 同股同日可有多个模板或运行来源。统计需显式选择按模板运行计数，还是对股票/日期/配置去重，不把重复来源当作独立样本。
- 模板名称用于展示，稳定 ID、revision、实际内容摘要用于追溯；跨版本合并统计须显式选择。
- 已确认保存结果和必要来源信息，不等于保存全部原始行情输入快照；完整重算仍受 B-I6 与 active generation 限制。

## 14. 增量补齐数据（用户已确认，具体契约待冻结）

### 14.1 规划原则

按本地 manifest、覆盖及成功状态规划实际缺口，经现有 `DataSyncService` 和 Planner/Worker/Staging/Verifier/Committer 发布。无缺口时跳过网络并按项目要求显示已有数据提示。

- 空库首次初始化获取目标研究窗口所需历史；后续只补新增尾部、内部缺口和新纳入的资料范围，不每次重拉八年。
- 不能只看 `MAX(date)`：末日已覆盖但中间缺数据时仍须发现孔洞。完整性依对象和数据类型判定，不套用股票池 95% 规则。
- 成功分区继续防重复拉取；失败/不完整不冒记成功，按现有失败日回补和显式重试规则处理，不增加无限自动重试。
- 上游修订需来源证据和明确版本策略，不提供无条件强制刷新绕过去重。已确认 qfq 等修复规则所需重拉按既有 ADR 执行，不扩大到无关成功数据。
- 统一前复权后，增量补齐继续沿用 [P5A 已确认的除权修复策略](P5A_PLAN.md)：检测除权事件时更新受影响股票所需历史范围，确保旧历史与新增尾部的复权尺度一致；其他股票的成功数据保持防重复约束。本次只记录该兼容要求，不启动重拉或改变已有同步实现。

### 14.2 各类型的增量单位

| 类型 | 增量规划建议 | 禁止的替代 |
|---|---|---|
| 指数行情 | 按指数、收益版本、应有交易日补尾部和内部缺口；目标为已完成交易日并考虑来源可用性 | 新增一个指数导致重拉所有成功指数；以前值补造行情 |
| 历史成分 | 补未保存的有效版本/快照及已识别的历史缺口 | 每天复制当前名单冒充历史；覆盖旧快照 |
| 历史权重 | 保存新公布或目标范围内尚缺的真实快照 | 强行按每天缺失处理定期发布数据；估算成官方权重 |
| 央行存款基准利率 | 首次取得起点前适用记录和窗口内调整；以后检查新增调整及已核实修订 | 每天复制相同利率成新公告；无新公告就写 0；成功无变化被误记失败 |

请求去重和成功状态键须区分新对象、新版本和原成功分区；检查频率及查询粒度待实际接口核验后冻结。利率长时间无新记录可能只是未调整，须区分上游错误和成功无变化。

### 14.3 点击分析边界与验收

- 点击股票只读本地已发布数据；不足时报告窗口不足或公共输入错误，不隐式触发网络补齐。
- 本地补齐后再次显式请求分析，按新输入版本计算并保存，不用旧缓存冒充新结果；同步完成是否自动刷新当前打开分析仍待确认。
- 后续离线验收：完整覆盖零 Provider 调用；尾部缺口只规划尾部；能发现中间孔洞；新指数不重拉旧指数；成分/权重无新版本不伪造日快照；利率成功无变化不写零；失败保留原成功数据；并发不重复抓取；修订可追溯。

本轮仅更新独立 P5B 计划，未实施这些服务、表或同步扩展，未迁移数据库或运行业务测试。

### 16.4 利率方案（期限、365 分母与单利已确认，历史映射及区间边界待确认）

以下区分已确认期限/换算与仍待讨论的历史映射和区间边界，不把项目代理换算当成银行实际定存合同的计息规则：

1. **当前默认品种/期限已确认**：用户对“所有窗口统一采用央行一年期存款基准利率”回复“行先这么配，有问题方便改就行”。据此默认央行人民币整存整取一年期，全部窗口统一，保留项目设置调整能力。这是项目当前配置，不是数学上唯一正确的期限，也不是固定一个利率数值。其他期限的数据仍可保存，不因项目默认档位只留一档。
2. **历史有效版本（仍为建议）**：每个历史收益区间使用当时有效且可用的记录；今天的利率不倒灌进此前已失效的区间。若采用“当前利率情景”，应另行明确而非默认混入。
3. **按实际自然日、365 分母、单利换算已确认**：用户明确回复“就按365+单利计算吧”。采用 ACT/365F，分母固定 365，闰日计入分子；利率不变的区间为 `annual_rate_decimal × calendar_days / 365`，不滚存利息。跨调息日按生效日期切分后求和仍为建议；具体日界建议采用前一收盘日期至本次收盘日期的左闭右开日期区间，作为按日代理而非精确小时计息。历史映射、端点归属与分段规则尚未一并确认。
4. **示例仅用于说明**：假设所选年利率为 1.50%（不是宣称当前值），且区间内不变，周五至周一跨 3 个自然日，区间代理收益为 `0.015 × 3 / 365 = 0.0001232877`，即约 `0.01232877%`；股票及沪深300各取相同两个交易端点的一条日收益，分别扣除此值。若中间调息，建议按各自生效天数分段相加，不对周末造股票观察。

### 16.6 简单收益率、alpha线性年化与252可调整默认（用户已确认）

用户明确要求“就按简单收益率和alpha线形年化”，据此个股与基准采用简单收益率 `P_t / P_prev - 1`。例如同一版qfq收盘价由10元变为10.50元，结果为5%；不采用对数收益，也不混用两种公式。指数是否包含现金分红仍须核验/确认，不能把qfq标签当作总回报保证。

alpha 是超额收益回归的截距，表达样本期内经过市场暴露调整后平均多出或少出的收益，不是股票当天涨幅，也不是简单减去沪深300涨幅。采用日收益回归，原始 alpha 对应日频；年化是为了统一展示尺度，不能把短期估计当成未来一年承诺。beta 无量纲，无需年化。

**已确认线性年化与默认因子**：`alpha_annualized = alpha_daily × periods_per_year`，默认 `periods_per_year=252`，允许在项目设置中调整。用户对“每年观察次数先设为252，并允许在项目设置中调整；与利率365分母分开保存”明确回复“可以”。日频alpha为0.02%时，默认年化alpha为5.04%；252是项目换算约定，不是对任何A股年度实际交易日数的断言。原始值、线性方法、实际因子与配置版本均保存；修改后仅用于新分析，在途任务使用冻结配置，旧结果不被改写。

年化因子与无风险利率ACT/365F的日历分母分别配置；自然日窗口不意味着股票每天有收益观察，不能把日频alpha直接乘以365。线性年化不采用 `(1 + alpha_daily)^N - 1`，也不等于窗口实际累计收益。缓存/请求身份须包含实际因子及配置版本，不能复用旧因子的结果；校验和配置界面细节在实现时补齐。

依据：[NBIM 风险调整收益方法第2.1.3节](https://www.nbim.no/contentassets/fdd69abfff8445cc967c30322b2d3968/factor-and-risk-adjusted-return_2024.pdf) 使用超额收益回归截距作为alpha，并将月频alpha乘以12年化；本项目选择同类的日频线性换算。[PerformanceAnalytics年化文档](https://search.r-project.org/CRAN/refmans/PerformanceAnalytics/html/Return.annualized.html) 区分算术与几何年化，将每年观察次数作为独立参数；本项目252默认由用户单独确认。
