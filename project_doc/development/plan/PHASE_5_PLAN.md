# StockManager 第五阶段计划：研究型回测与 CAPM 分段建设

StockManager 是 A 股研究型筛选平台，禁止自动交易；CAPM 估计和回测结果仅供研究参考，不构成任何投资建议，也不代表未来收益。

本阶段的架构与任务拆分代理为 Codex；实现、测试、调试与代码审查代理为 DeepSeek V4 Flash；Qwen3.8:27b 仅在实现验收后按完整任务包起草注释和技术文档。

## 1. 阶段定位

P5 拆成两个可以独立验收、按顺序交付的子阶段：

1. **P5-A 研究型回测**：先把现有筛选模板转换为历史目标权重，使用第三方开源引擎完成日频、离线、可复现的组合回测闭环。
2. **P5-B CAPM**：在 P5-A 的股票与组合收益序列契约稳定后，再估计 alpha、beta、拟合质量和残差风险。

P5-A 不依赖无风险利率或 CAPM 才能完成；P5-B 消费 P5-A 的标准化收益结果，不反向改变回测引擎。CAPM 数学逻辑由 StockManager 自己维护为纯函数；投资组合回测优先通过适配器集成开源 `bt` 包，禁止把第三方类型扩散到 Domain、Storage、Provider、Web 或规则层。

## 2. 依赖与可行性

### 2.1 强制依赖

- P5-A 依赖 P4 的数据库无关只读端口、数据快照和并发读取服务。
- P5-B 依赖 P5-A 已冻结的收益序列、回测结果和运行元数据契约。
- 现有 A 股交易日历、`Asia/Shanghai` 时间语义和显式复权元数据。
- `DataSyncService` 继续作为任何新增外部数据的唯一入口。

### 2.2 当前数据缺口

现库仅保留约 360 个自然日的前复权日线。数据缺口按子阶段处理：

- P5-A 必须处理研究历史窗口、历史时点股票池、复权与分红口径，避免生存者偏差和前视偏差。
- P5-A 可以在没有无风险利率的情况下完成，并可先提供普通基准净值对比。
- P5-B 才强制要求基准指数收益序列、无风险利率来源与频率。
- P5-B 的资产、组合、基准和利率必须使用一致的交易日对齐与显式元数据。

因此，P5-A 可以先形成可用回测产品；P5-B 的数据决策不会阻塞 P5-A，但会决定 CAPM 结果能否被称为正式研究证据。

## 3. 开源回测包选型

### 3.1 默认候选：`bt`

选择理由：

- MIT 许可，保留项目未来使用和分发弹性。
- 当前发布版本支持 Python 3.9 及以上，与项目 Python 版本范围兼容。
- 以 pandas 价格矩阵和附加信号矩阵为主要输入，与 P4 的批量读取结果容易适配。
- 组合、权重、再平衡和指标分析模型适合把现有筛选结果转换为研究组合。
- 框架定位是回测研究，不需要为 StockManager 引入实盘连接。

局限：`bt` 不会自动替 StockManager 正确处理全部 A 股涨跌停、停牌、T+1、整手和交易费用规则。这些必须由 StockManager 的输入适配器、可交易掩码、成本函数和验收 fixtures 明确实现，不能默认相信第三方行为。

### 3.2 备选：RQAlpha

RQAlpha 对 A 股日频、交易日历、撮合和自定义 DataSource 支持更完整，且当前元数据声明支持 Python 3.14。但其许可证明确限制商业使用，框架还包含模拟与实盘相关能力。只有在 `bt` PoC 无法满足核心 A 股约束、用户确认许可边界并批准依赖后，才允许作为备选；集成时仍必须禁用任何实盘模式。

### 3.3 不作为默认选择

- `vectorbt`：适合大规模参数矩阵，但采用 Apache 2.0 + Commons Clause，且复杂 A 股成交约束需要较多自定义。
- `backtrader`：事件模型成熟，但官方包维护节奏慢且采用 GPLv3，不优先引入。
- `zipline-reloaded`：安装和数据 bundle 复杂，公开文档的 Python 支持范围落后于当前项目运行环境。

### 3.4 选型门禁

P5-A0 必须先在隔离环境完成 PoC，不得先把依赖加入主项目。PoC 至少验证：

- 当前项目 Python 版本可安装并运行。
- 可从 P4 读取结果构造输入，不调用包自带在线数据源。
- 多股票日频组合、按交易日再平衡、交易成本、停牌不可交易和稳定输出可实现。
- 同一 fixture 重复运行结果一致。
- 第三方包没有进入 Domain、Rules、Provider、Storage 公共接口。

PoC 通过后才可固定版本并写入 `pyproject.toml`。

### 3.5 选型证据

- `bt` 官方仓库与许可证：https://github.com/pmorissette/bt
- `bt` 当前 PyPI Python 与许可证元数据：https://pypi.org/project/bt/1.2.0/
- RQAlpha 自定义数据源文档：https://rqalpha.readthedocs.io/zh-cn/develop/development/data_source.html
- RQAlpha 项目许可证：https://github.com/ricequant/rqalpha/blob/master/LICENSE
- RQAlpha Python 版本与依赖元数据：https://github.com/ricequant/rqalpha/blob/master/pyproject.toml
- vectorbt Commons Clause 许可证：https://github.com/polakowo/vectorbt/blob/master/LICENSE.md
- backtrader GPLv3 许可证：https://github.com/mementum/backtrader/blob/master/LICENSE

第三方 `bt` 仅允许存在于 `BtEngineAdapter` 及其专用测试中。CAPM、信号生成、数据读取和对外结果模型不得导入 `bt`。

## 5. 研究数据契约

每次回测运行必须固定并输出：

- `run_id`、模型/引擎版本和配置摘要。
- 数据集 ID、来源、生成或同步时间。
- `Asia/Shanghai` 时区和目标交易日范围。
- 股票池定义及其时点语义。
- 明确资产复权方式；P5-A 若配置普通基准对比，资产与基准复权不一致时拒绝运行。
- 信号生成时间、可用于成交的最早交易时点。
- 初始资金、再平衡周期、成本、滑点、整手和不可交易规则。

P5-B CAPM 运行在上述元数据基础上另外固定：

- 基准代码和基准数据来源。
- 无风险利率来源、单位、年化方式和对齐规则。
- CAPM 估计窗口、最小观察数和年化方式。

## 6. P5-A：回测语义

### 6.1 信号与成交时间

- 默认研究语义拟定为：交易日 T 收盘后形成信号，最早在下一有效交易日 T+1 执行。
- 禁止使用 T 日收盘价计算信号后仍按 T 日收盘价无摩擦成交。
- 若用户选择其他执行时点，必须由明确配置和可用数据证明没有前视。

### 6.2 A 股约束

必须显式配置并测试：

- 停牌时不可成交。
- 涨停买入和跌停卖出的可成交规则。
- 股票最小委托单位与零碎股处理。
- T+1 卖出限制。
- 佣金、印花税、过户费、最低佣金和滑点。
- ST、退市和上市不足窗口的股票池行为。

P5 不允许把这些规则散落在 Web 或策略脚本中；它们属于回测适配与交易约束配置。

### 6.3 结果

标准化结果至少包含：

- 组合净值与基准净值序列。
- 每日收益、累计收益、最大回撤和波动率。
- 持仓、目标权重、实际权重、成交和未成交原因。
- 换手率与全部成本。
- 样本期、股票池、复权、基准和数据版本。
- 生存者偏差、前视偏差和数据缺口警告。

P5-A 完成时不要求 CAPM alpha/beta。它必须先稳定输出每日组合收益和资产收益，供 P5-B 直接消费。

## 7. P5-B：CAPM 契约

### 7.1 模型

使用超额收益形式：

```text
R_asset,t - R_f,t = alpha + beta * (R_market,t - R_f,t) + epsilon_t
```

P5-B 不默认把无风险利率设为零。若使用固定利率、零利率或本地手工曲线，必须由用户明确批准并写入运行元数据。

### 7.2 输出

至少包含：

- `alpha`
- `beta`
- `r_squared`
- `residual_volatility`
- `observation_count`
- `window_start`、`window_end`
- 数据与复权元数据
- 缺失值、样本不足或零方差原因

滚动 CAPM 与全窗口 CAPM 使用同一纯函数核心；窗口按交易时段计数，不使用自然日前一天代替上一交易日。

### 7.3 异常与边界

- 资产、基准和利率序列按交易日内连接，禁止位置硬拼。
- 重复日期、无序输入、非有限值和复权不一致显式失败。
- 市场超额收益方差为零时不返回虚假 beta。
- 样本数不足时返回结构化“不可估计”结果或明确业务异常，语义在 P5-B0 冻结。

## 8. 任务分解

### P5-A0：回测包隔离 PoC 与 ADR

- 在临时隔离环境验证 `bt` 安装、许可证、Python 兼容性和核心功能。
- 用固定小型 A 股 fixture 接入 P4 读取结果。
- 证明第三方依赖可以被 `BacktestEnginePort` 隔离。
- 若核心约束无法满足，记录失败证据，再评估 RQAlpha；禁止静默换包。

验收：产出选型 ADR、锁定版本建议、依赖清单、许可证说明和最小运行证据。

### P5-A1：回测领域模型与接口冻结

- 定义回测规格、目标权重、成交原因、资产收益、组合收益和标准回测结果。
- 定义 `BacktestEnginePort`，接口中不得出现 `bt` 类型。
- 固定数据缺失、复权不一致和不可交易的错误语义。

验收：Domain 不依赖 pandas、bt、SQLite、Provider 或 Web。

### P5-A2：回测历史数据集与股票池

- 设计独立于 360 天运行窗口的研究历史策略。
- 通过 `DataSyncService` 同步或导入历史时点股票池与回测所需日线。
- 数据集继续记录来源、时间和复权。

验收：所有新增外部数据只由同步服务进入本地存储；重复同步、失败状态、锁和限速规则保持有效。

### P5-A3：`bt` 引擎适配器

- 将 P4 数据和目标权重转换为 `bt` 输入。
- 将 `bt` 输出归一化为 StockManager 领域结果。
- 禁用包自带在线数据下载路径。
- 第三方异常转换为明确集成异常并保留异常链。

验收：除适配器和专用测试外，项目代码不得导入 `bt`。

### P5-A4：筛选信号历史化与反前视控制

- 将现有模板在每个历史评估日生成的结果转换为目标权重。
- 明确等权、评分加权或其他组合规则；默认规则由用户批准。
- 强制信号时间与成交时间错位，保存信号快照。

验收：人为构造 T 日信号，证明不可能在 T 日已知价格成交；历史股票池按时点读取。

### P5-A5：A 股成本与可交易约束

- 实现停牌、涨跌停、T+1、整手、费用和滑点适配。
- 未成交必须保留原因，不得自动按理想价格成交。

验收：覆盖停牌、涨停买、跌停卖、资金不足、最低佣金、零成交量和退市边界。

### P5-A6：回测服务、结果存储与独立验收

- `BacktestResearchService` 编排 P4、历史信号和回测端口。
- 保存运行配置、数据快照、结果摘要和可追溯明细。
- API/CLI 只读本地数据，不触发隐式同步。
- 对串行与 P4 并发读取做端到端基准。

验收：同一 `run_id` 可追溯完整输入；响应不泄漏本机路径；服务断网可运行；P5-A 可以在没有 CAPM 和无风险利率时独立标记完成。

### P5-B0：CAPM 决策、领域模型与数据契约

- 固定基准指数、无风险利率来源、收益类型、估计窗口和最小观察数。
- 定义收益观察、利率观察、CAPM 请求、可估计/不可估计结果和错误语义。
- 通过 `DataSyncService` 同步或导入获批准的基准与利率数据。

验收：未确认的基准或利率不会被隐式填充；Domain 不依赖 pandas、bt、SQLite、Provider 或 Web。

### P5-B1：收益构造与对齐

- 直接消费 P5-A 的标准化资产/组合收益序列。
- 实现资产、组合、基准和利率按交易日对齐。
- 记录缺失、重复、无序、停牌和复权不一致的处理结果。

验收：不能通过位置拼接错误日期；输入顺序变化不改变结果。

### P5-B2：CAPM 纯函数

- 实现全窗口与滚动 CAPM。
- 输出 alpha、beta、R²、残差波动、观察数和残差序列。
- 提供确定性的数值容差和结构化不可估计结果。

验收：使用人工可计算 fixture 验证 alpha、beta、R²、零方差、缺失值、无序、重复和样本不足。

### P5-B3：个股、组合与 P6 残差集成

- 为个股和 P5-A 回测组合提供统一 CAPM 分析服务。
- 将滚动残差以版本化研究数据提供给 P6，不把 CAPM 逻辑复制到 P6。
- API/CLI 只格式化结果，不实现回归。

验收：同一收益序列在个股与组合入口使用同一数学核心；P6 只能消费结构化 CAPM 输出。

### P5-B4：样本外验收、审查与文档

- 在时间分段中检查 beta 和 alpha 稳定性。
- 报告基准代理、样本期、估计窗口和 CAPM 模型局限。
- 分别记录 P5-A 与 P5-B 的测试和验收证据。
- 验收后更新文档并同步 `project_doc`。

验收：不把正 alpha 表述为已验证未来收益；全部离线测试通过并由 DeepSeek V4 Flash 技术验收。

## 9. 关键决策门禁

以下决定按子阶段分别设门禁：

### P5-A 门禁

1. 回测首选 `bt` 是否获批准；失败时是否允许评估 RQAlpha 的非商业许可。
2. 回测使用的复权方式。
3. 研究历史长度与本地存储容量预算。
4. 股票池是否要求严格 point-in-time；若暂用当前股票池，结果必须标记生存者偏差。
5. 信号权重方式、再平衡周期、执行时点和成本参数。

### P5-B 门禁

1. CAPM 基准指数或基准组合。
2. 无风险利率来源和口径。
3. CAPM 使用的复权和收益口径。
4. 估计窗口、最小观察数和年化方式。

## 10. 完成定义

1. P5-A 回测与 P5-B CAPM 均只读取本地数据并通过 P4 端口访问。
2. 第三方回测包被适配器完全隔离，允许未来替换。
3. 不存在自动交易、经纪商连接或实盘模式入口。
4. P5-A 可在没有 CAPM 的情况下独立验收，且稳定输出资产与组合收益序列。
5. P5-B 只消费 P5-A 标准结果，不反向依赖 `bt` 或复制回测逻辑。
6. 复权、基准、利率、交易日、信号时间和成本全部显式记录。
7. 关键 A 股不可交易场景有离线测试。
8. 回测与 CAPM 结果均可由固定 fixture 确定性复现。
9. DeepSeek V4 Flash 分别完成 P5-A、P5-B 的实现、测试、调试和代码审查验收。
10. 验收后的文档包含规定 frontmatter，并同步到 `/Users/douzihao/StockManager/project_doc`。
