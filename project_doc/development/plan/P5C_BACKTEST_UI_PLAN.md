## 0. 目标与场景

把现在散落在筛选工作台里的回测功能（「回测基础数据」「策略模版」「回测结果」三块）抽出来，建成一个**独立的「回测系统」整页视图**，交互切换模式与现有「数据同步 ↔ 工作台」一致；同时扩展策略表达能力（入场/退出多策略并列、独立多档止盈）与回测运行能力（自定义历史窗口、单股回测、运行级费用配置），并把费用/整手从执行政策参数中提升为运行级字段。

目标用户：自用研究型用户，本地优先、断网可用，所有输出仅供研究参考，不构成投资建议。

## 1. 已确认需求（2026-09-04 用户逐项确认）

以下各项均为“用户已确认”；实现细节中未被用户拍板的点按第 8 节“建议默认与待决项”处理。

### 1.1 页面与导航

- D1. 新增第三个整页视图 `#backtest-view`（名称「回测系统」），切换方式与「数据同步 ↔ 工作台」相同：工作台顶部提供进入「回测系统」的入口，回测页顶部提供「← 工作台」返回；不做子标签页、不做新路由服务器。
- D2. 工作台内现有「回测基础数据 / 策略模版 / 回测结果」三块**迁走删除**，回测相关控件只存在于回测系统页。
- D3. 回测系统页保留**筛选模板选择器**（回测资格池来源）；筛选模板的规则启停/参数/组合逻辑编辑仍回筛选工作台完成，不在回测页内嵌规则编辑器。
- D4. 回测页布局：左列=回测基础数据（运行环境）、中列=策略模版（模板选择 + 策略编辑器）、右列=回测结果（本次结果 + 历史运行列表）。
- D5. 视觉沿用现有 `styles.css` 设计体系；面板收起/展开、浏览器偏好记忆、窄屏纵向堆叠等既有交互沿用。

### 1.2 回测基础数据（运行环境，每次现填、不存入策略模板）

- D6. 字段：回测窗口、初始资金（默认 1,000,000）、最大持仓数、回测并发 Worker（1~16，默认 2）、股票代码（可选，逗号分隔多只）、费用组（佣金费率/印花税率/过户费率/最低佣金/整手股数）。
- D7. 窗口支持**自定义起止日期（精确到日）**与快捷预设（近 1/3/5/8 年）。预设终点=本地最新已完成交易日；自定义终点不得晚于最新已完成交易日、起点不得早于本地数据覆盖起点，超界校验报错，不静默截断。
- D8. 费用/整手在 UI 上以**小数比例直接填**（佣金 0.0003、印花 0.0005、过户 0.00001、最低佣金 5 元、整手 100），提供「恢复默认」按钮；校验值域非负。
- D9. 「最大持仓数」以回测基础数据为**唯一入口**，提交时统一覆盖分配政策 `max_positions` 参数（顺带修正现状：工作台左栏 `#bt-positions` 输入实际不生效、仅分配政策参数生效的冗余问题）。
- D10. 费用/整手在后端从 `ashare_execution_v1` 参数表**正式移除、改为 run 级独立字段**；策略模板不保存运行环境数值；历史运行记录的读取保持兼容（不迁移改写旧行，旧行展示时从其执行政策参数还原费用展示）。
- D11. 「忽略资格（纯政策）」开关在未填任何代码时禁用并提示；该模式至少填 1 个代码才有意义。

### 1.3 单股回测

- D12. 代码输入支持多只（逗号分隔，格式同筛选页 sh./sz. 前缀）；恰好 1 只时进入“单股模式”。
- D13. 单股模式提供开关：「套用模板资格」（逐日用所选模板判定该股是否通过，通过日才可入场）与「忽略资格纯政策」（整段窗口该股一直可交易，买卖完全由入场/退出/止盈政策决定）。
- D14. 单股（忽略资格）资金口径：买入金额=净资产×(1−现金保留比例)，最大持仓视为 1；整手、费用、T+1、涨跌停等执行约束照常。
- D15. 恰好 1 只代码时，「排名 / 分配」区自动置灰固定默认（排名不参与、分配按 D14 口径）；多只代码时两者照常生效。
- D16. 单股模式窗口同样支持自定义起止日期与预设（同 D7）。

### 1.4 策略模版编辑器

- D17. 入场组、退出组支持多政策并列：每组 1~5 条，允许**同一政策多个实例**（各自不同参数）；组合逻辑 OR/AND 可切换、默认“任一满足 (OR)”。
- D18. `eligibility_enter_v1`（合格即买）作为**普通入场项**参与组合；OR 组合下若与其它入场条件并列，其它条件不会生效，UI 需给出黄色提示说明。
- D19. 退出组只放“全额退出型”政策（资格失效/跌破均线/高于均线卖出/持有到期等）；**止盈减仓独立成区**，不参与退出组 OR/AND。
- D19b. 同一持仓在同一收盘决策内既有退出组（全额退出型）命中又有止盈档命中时：**全额退出优先**——当日只按退出组执行一笔清仓，止盈档当日不执行（不做同日分笔）；止盈减仓只在**没有全额退出信号**的交易日生效，按 D20 多档低→高执行。
- D20. 止盈区可配**多档**（每档=触发涨幅+减仓比例，上限 5 档）；同一日多档命中按低档→高档逐档执行。
- D21. 调仓/分配/排名/执行四类保持**单选**。执行类不再显示费用/整手参数（已移入基础数据 D8/D10），仍可选择执行模型（当前唯一 `ashare_execution_v1`）。
- D22. 默认配置：入场=`eligibility_enter_v1`×1；退出=`eligibility_exit_v1`×1；止盈档空；费用/整手=默认组；窗口默认自定义日期模式；持仓/现金/Worker 沿用现有默认。
- D23. 策略可**命名保存/加载/删除/另存为/校验**，机制对齐筛选模板：JSON 模板目录、revision 递增、系统内置默认策略 1 份；模板只存“策略部分”（D17~D21 的结构），不存运行环境。

### 1.5 运行与结果

- D24. 沿用单任务并发：同一时刻只跑 1 个回测任务，运行中可取消；页面切走后任务在后台继续，返回仍可见进度；进度/状态/失败原因展示交互与“数据同步”页面一致。
- D25. 回测系统页提供**历史运行列表**（时间倒序），全部保留、不提供删除；点击回看该次的指标/净值/订单/参数快照。
- D26. 本次结果展示：指标摘要 + **自绘净值曲线图**（canvas/SVG，本地实现，无外部资源）+ 完整订单明细（替代现状“最近 10 个净值点/20 条订单”文本截断）。

### 1.6 买卖点时间戳叠日K（2026-09-04 用户补充）

- D29. 回测本次结果与历史回看的成交/订单明细中，**每一行可点击**；点击后在该股日 K 上叠加“本次回测中该股的买入/卖出点（带时间戳）”复盘浮层，展示与交互复用现有日 K 渲染（缩放/平移/悬停同款），不扰动「个股研究」区的选中状态。
- D29b. 标记画在**成交日**那根 K 线上：买▲（上方）/卖▼（下方）+ 价格 + 股数，悬停显示完整日期、方向、价格、数量与成交详情；标签随缩放自动取舍避免密集重叠；同一成交日同向多笔默认合并为单标记（合计股数），气泡内列出各笔。

## 3. 交互流程

1. 顶部进入「回测系统」→ 左栏填运行环境（窗口预设或自定义日期、现金、最大持仓、Worker、费用组、可选代码与资格开关）→ 中栏选筛选模板 + 加载/新建策略（入场/退出/止盈/四类单选）→ 点「运行回测」。
2. 提交校验（模板 revision、政策白名单、组合非空、日期边界、忽略资格需代码、单任务占用）。
3. 运行中：单任务进度 + 阶段文案（信号构建/回测执行），可取消；切走视图任务继续。
4. 完成后右栏显示指标摘要 + 净值曲线 + 订单明细与执行限制警告；同时写入历史列表。
5. 历史列表点击回看任意一次运行的完整结果与参数快照。

## 4. 数据口径与运行约束（沿用既有，不得改变）

- 时间基准 `Asia/Shanghai`；终点“最新已完成交易日”按交易日历与 Cutoff 计算，不用自然日。
- 复权沿用前复权（QFQ，回测数据统一前复权），不新增复权选择。
- 本地优先：回测只读本地 SQLite，断网可运行；数据由 `DataSyncService` 同步，本模块不触碰 Provider。
- 筛选资格逐日口径、PIT 防未来函数、规则门禁、八年覆盖前提、执行模型（T+1、次日开盘成交、整手、停牌/涨跌停、费用、滑点）语义不变；回测引擎仍由 Backtrader 驱动但输出为领域契约。

## 5. 契约与后端改动（方案层，实施前细化为接口明细）

### 5.1 策略规格模型（`research/models.py` 等）

- `ResearchStrategySpec`：`entry_policy/exit_policy` 单对象扩展为“条目列表 + 组合操作符”（保持旧对象可解析的兼容层）；新增止盈档结构；`PolicyKind` 语义维持六类，止盈档作为独立机制表达（不与 EXIT 混排）。
- 新增 run 级字段：费用 4 项、整手、标的代码（空=全资格池）、窗口起止、资格开关/模式；`execution_policy` 从参数表移除费用/整手（参数白名单同步更新）。
- 策略模板模型：命名 + revision + 策略部分 JSON（对齐 `templates/` 的 JsonTemplateRepository/校验/指纹体系，新增一套 strategies 的 repository/compiler 校验）。

### 5.2 引擎（`backtest/`）

- `next()` 每日循环：入场组按操作符对“候选=资格名单内(或忽略资格模式的输入代码)且未持有”逐股求值；退出组按操作符对持仓逐股求值；止盈档独立执行：仅对当日**没有**全额退出信号命中的持仓，按命中档位（低→高）逐档减仓；同一持仓同日既有全额退出又有止盈命中时全额退出优先、只一笔清仓（见 D19b）。
- `ExecutionParameters` 来源从执行政策参数改为 run 级字段；`compute_fees`/`decide_buy`/`decide_sell` 语义不变。

### 5.3 服务与存储

- `ResearchBacktestService.submit()` 入参扩展（模式、代码、自定义日期、费用/整手）；策略指纹与 provenance 同步纳入新字段；历史 `backtest_runs` 读取兼容旧 spec（旧行展示还原费用，不迁移改写）。
- 新增策略模板 CRUD 服务（或并入现有模板层）与对应 API：`GET/POST /api/research/strategies`、`PUT/DELETE /api/research/strategies/{id}`、`POST /api/research/strategies/validate`（名称与端点实施前按 `P3_WEB_API.md` 风格定稿）。
- 回测结果/净值/订单接口沿用现有分页能力；运行列表接口补充策略模板引用与参数快照展示字段。
- `/api/bars` 扩展支持按起止区间拉取单股日 K（或等价新参数/接口，满足 D29d 的 1~8 年窗口覆盖），仅读本地 SQLite。

### 5.4 前端日K复用（买卖点复盘）

- 现有日 K 渲染（`app.js`：`drawKline`、悬停/缩放/平移与 `_klineCache` 状态）抽取为**可复用组件/渲染函数**：入参（canvas、bars、可选 markers、可选 info 文案），回测复盘浮层与「个股研究」共用同一实现且互不污染状态。
- markers 层：按 `trading_day` 定位到 bar 索引；买点在 bar 上方、卖点在下方绘制箭头及价格/股数标签；缩放时按可见区间取舍标签、悬停气泡展示 D29b 明细；同日同向多笔合并按 D29b 规则。

## 6. 任务拆分与依赖（建议实施顺序，待复核后细化）

## 7. 测试与验收（每项可判定）
