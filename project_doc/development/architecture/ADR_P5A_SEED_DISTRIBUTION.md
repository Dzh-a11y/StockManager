# ADR：P5A 八年数据种子离线交付方案（草案）

## 状态

**已接受（accepted）**：用户于 2026-09-01 确认复权口径统一采用 qfq、除权断层对策采用方案 a（除权后重拉受影响股票）。种子生成与导入实现属于 P5A-1，本 ADR 作为 P5A-1 与打包流程的设计依据。

## 背景

P5A（`development/plan/P5A_PLAN.md`）要求本地行情历史从约一年扩展至八年，约 5,431 只股票 × 1,938 根日线 ≈ 1,050 万行，数据库预计约 1.5~1.7 GB（当前一年数据 124 万行 / 207 MB）。

在线拉取成本（2026-09-01 实测，见下文“基准事实”）：全市场八年前缀补齐约 3.8~4 小时；日常尾部增量约 13 分钟/交易日。用户此前以单文件 exe（`scripts\build_windows_exe.bat` → `dist\StockManager.exe`）分发程序，本次计划把八年数据库随程序交付，避免用户在线等待数小时。

本 ADR 记录分发形态决策、种子数据契约与必须处理的风险。复权口径、成交时点、A 股约束等级等 P5A 待决策项（`P5A_PLAN.md` 第 1.2 节）不因本 ADR 而改变。

## 基准事实（2026-09-01 实测，Apple Silicon / Python 3.14 / baostock 0.9.3）

- 单只股票一次请求拉八年（2018-09-01 ~ 2026-08-31，1,938 行）：平均约 2.3 s，波动 0.2~4.6 s；重复三次单请求为 0.58 / 2.21 / 2.40 s，波动来自 Baostock 服务端，与客户端无关。
- 请求耗时与返回行数强相关：8 年 1,938 行 ≈ 2.3 s；最近 5 天 5 行 ≈ 0.14 s；单日 1 行 ≈ 0.18 s。按年分段（8 × 1 年请求）不省时，反而更慢。
- 全市场（`query_all_stock` 2026-08-31 快照，A 股口径 5,431 只）估算：八年全量 ≈ 3.5 h 纯查询 + 0.2 s/请求限速 ≈ 3.8~4 h；尾部增量（最近 5 天）≈ 13 min；区间补齐（如 120 个交易日 ≈ 0.2~0.3 s/只）≈ 25 min。
- 基准脚本：`scripts/bench_baostock_8y.py`（仓库内，网络基准脚本，不属于产品代码）。

## 决策（草案）

### 1. 主程序不内嵌数据库

- 单文件 exe 内嵌八年 SQLite（约 1.5~1.7 GB）被否决：exe 体积过大、每次启动解压、系统盘临时目录需约 2 倍空间、杀软扫描慢。
- 主程序保持现有打包方式（体积不变）；数据库以**独立种子文件**交付。

### 2. 种子数据库独立下载

- 种子为八年口径的 `market.sqlite3` 快照（约 1.5~1.7 GB，VACUUM 后分发；SQLite 文件跨平台通用，macOS 生成、Windows 可用）。
- 用户首次运行时选择：a) 在线拉取（约 4 h）；b) 下载种子导入。种子下载与校验由程序引导，不绑定同步 HTTP 请求。
- 种子文件必须携带可校验元数据：`generation`（不可变数据版本）、覆盖起止日（`coverage_start`/`coverage_end`）、sha256、生成时间、复权口径、股票池口径。校验失败拒绝导入。

### 3. 口径与现状一致：qfq

- 当前 `daily_bars` 表主键为 `(code, trading_day, adjustment)`，现库按 **qfq** 存储（`config` 的 `technical_adjustment: qfq`）。种子按 qfq 预拉，与现有数据、规则、Web 工作台口径一致，可直接拼接。
- 结构上支持多口径并存；未来若复权策略决策改变（P5A 1.2 待决策项 #1），种子生成口径随之调整，不改变本方案形态。

### 4. 首次启动对账与防覆盖

- 工作副本（用户数据目录）已存在时，**严禁种子覆盖新数据**；沿用“成功即锁定、拒绝重复拉取”红线（AGENTS.md 第 11 章）。
- 对账规则：工作副本缺失前缀（早于工作副本 `coverage_start` 且种子可覆盖）→ 从种子补齐；缺失尾部 → 在线增量同步；两者都缺 → 按需补齐。
- 种子 generation 旧于工作副本时，以工作副本为准并提示；种子仅作为“初始基线”，不替代增量同步。

### 5. 日常增量与除权处理

- 每次启动照常执行尾部增量（最新已完成交易日，约 13 min/次）。
- qfq 除权断层风险（见“风险与未决项”）：发生除权的股票按**对策 a** 处理——检测除权事件后后台重拉该股票八年 qfq（单只约 2.3 s；A 股年除权约 2,000~3,000 只，一轮约 1.5~2 h，可分批）；重拉完成前该股票不得宣称与在线数据在除权点等价。

### 6. 种子生成流程

- 种子生成 = P5A-1 八年补齐（`backfill_runs_v2`/`backfill_chunks_v2`、generation 提交）的**离线模式**：在打包机执行同一套 backfill 代码预拉八年（约 4 h），校验完整性后 VACUUM 并生成元数据，随版本发布。
- 在线补齐与离线种子共用同一实现，避免两套逻辑分叉；Provider 请求保持串行、受控速率（P5A 8.3）。

## 备选方案与否决理由

| 方案 | 结论 | 理由 |
|---|---|---|
| 单文件 exe 内嵌种子 | 否决 | 体积、启动解压、临时目录、杀软问题 |
| 安装包/目录内随包分发种子 | 备选 | 与独立下载等价，仅分发渠道差异；当前用户倾向独立下载 |
| 种子存不复权 + 复权因子 | 备选 | 不可变、无拼接断层，但需自实现复权计算，且复权策略未决 |
| 种子按 hfq 存 | 否决（当前阶段） | 与现有 qfq 规则/界面语义不一致，切换影响面大 |

## 风险与未决项

1. **qfq 种子会“过期”（失真而非陈旧）**：前复权历史价格以最近一次除权日为基准整体回算；除权后种子段与增量段在拼接点断层，绝对价格类规则（如 N 日新高、价格区间）在除权日附近失真。**已决策（2026-09-01）：对策 a**——检测除权事件，后台重拉该股票八年 qfq（单只约 2.3 s；A 股年除权约 2,000~3,000 只，一轮约 1.5~2 h，可分批）。重拉实现随 P5A-1 落地。
2. **Baostock 数据再分发合规**：当前确认仅个人使用，不对外分发；若未来对外分发，必须先确认条款允许。
3. **种子陈旧度**：种子越旧，首启补齐尾差越多；发布节奏应控制种子年龄，或提供区间补齐（约 25 min/120 交易日）能力。
4. **复权口径**（P5A 1.2 #1）：**已决策（2026-09-01）——筛选输入与回测成交统一采用 qfq**；本方案与之一致，锁定 qfq 为当前复权策略。
